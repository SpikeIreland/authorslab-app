# Findings Register

Method-level lessons discovered during station work — patterns, failure classes,
better ways of doing things — get dropped here for the SIS Methodology chat to
curate into process improvements.

## Conventions

- One finding per file. Filename: `YYYY-MM-DD-station-shortdescriptor.md`
  (e.g. `2026-07-24-platformdev-anonymous-approvals.md`).
- Header block: **Finding**, **Discovered by** (station chat), **Discovered
  during** (dispatch or activity), **Evidence** (file + line, log excerpt, or
  test artifact).
- Body: what pattern this is an instance of, what should change, and where the
  discipline gets applied next.
- If a finding is a duplicate of an already-recorded one, reference it and add
  the new evidence rather than open a new file.

## Register status

The authoritative findings register lives in the SIS Methodology chat's
workspace and turns entries here into process improvements. This folder is the
inbox — anything dropped here is expected to be picked up, tagged (F-###), and
routed back into the method.
