## 1 · What exists today, verified

Text-free cover **artwork**, in the private `cover-assets` bucket, generated by 5.2 (gpt-image-1, provenance in `cover_assets.source`):

- **Portrait concepts:** 1024×1536 PNG, ~2.4–2.7MB each (aspect 1:1.5)
- **Wraparound jacket** (Veil): 1536×1024 PNG — a *visualisation* asset (back|spine|front in one scene), not a print file

**No composed cover file exists anywhere.** Typography is composited app-side by the cover composer, whose UI is not yet built (backend live since July). So the honest sentence for any proposal: **today we produce cover art awaiting typography — nothing in the system is a distributor-uploadable cover file yet.** Publishing's "art, ready for typography" boundary is exactly right.

## 2 · Against KDP ebook spec (checked today at the source)

KDP's current requirements: **recommended 1600×2560** (ideal ratio 1.6:1), minimum 500px shortest side, JPEG preferred, ≤5MB, RGB, 300 DPI stated.

- Raw art (1024×1536): **displays** (short side 2× the minimum) but is **60% of recommended height**, ratio 1.5 vs ideal 1.6, and PNG not JPEG. Fine for screens; below Amazon's quality recommendation as-is.
- The composer's specced export (TDP-DT-01: **1600×2560**) **matches KDP's recommendation exactly** — the July number was chosen for this. At export the art layer upscales ~1.67×, which softens it slightly; typography renders at full resolution and stays crisp. Ebook-grade is therefore **claimable on composer completion**, with that one caveat.

## 3 · Against print (KDP Print / IngramSpark: 300dpi full-wrap PDF, computed spine + bleed)

**Not achievable from current assets, and not close.** A 5×8″ front alone at 300dpi is 1500×2400 before bleed; a full wrap for a ~300-page book is roughly 3300×2550. Our jacket render is ~45% of that on the long edge, and print-wrap composition (spine width from page count, bleed, PDF/CMYK) is explicitly out of TDP-DT-01's scope. Print-grade requires **Stage 3 generation upscaling (specced July, unbuilt)** plus a print-wrap pipeline that has never been designed.

## 4 · For the SAY / DON'T-SAY-YET table

- **SAY (on composer completion):** AI-generated cover concepts with author-controlled typography; ebook cover export at Amazon's recommended resolution.
- **SAY (today):** cover art direction and full-jacket visualisation.
- **DON'T SAY YET:** "print-ready covers", "distributor-ready cover files", or anything implying the cover file Hachette's pipeline receives comes from us. That last mile is real work with a specced-but-unbuilt stage in the middle, and Oliver's formatting questions land exactly here.
